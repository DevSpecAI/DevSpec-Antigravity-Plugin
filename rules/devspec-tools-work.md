# DevSpec tool shapes: work

Call these DevSpec tools directly (`ServerName: "devspec_devspec"` on `call_mcp_tool`) with the shapes below, without reading their `.json` schema files.

- `?` marks an optional parameter. Ids that take a UUID or an 8-character short code say so; the rest need the full UUID.
- Never pass what `PreToolUse` stamps: `connection_id`, `project_id`, `local_session_id`, `agent_name`, `request_ref` and `provenance_ref`.
- Most tools also take `git_remote` (your `git remote get-url origin`) and `pinned_project_id` (from `.devspec/project.json`), which say which project when none is stamped. Pass them only when a result asks which project you mean.
- Writes take `work_claim_ref`: pass the one `claim_work_item` returned on a write about that claimed task when you hold more than one claim.
- When a result names a parameter these shapes do not show, read that tool's schema file before calling it again.

## Session reply

- `post_session_message`: `{ message, complete_turn?: boolean, reply_to_message_id?, system_notice_ids?: string[] }` (`complete_turn: true` on your final answer; `system_notice_ids` only on a notice reply, never with `reply_to_message_id`). The plugin and DevSpec fill in everything else this tool takes, for the turn it answers: never pass `provenance_ref`, `session_id`, `command_turn_id`, `command_message_id`, `command_turn_unbound`, `local_turn`, `turn_kind`, `phase`, `needs_input`, `work_trail`, `trail_events`, `agent_stats` or `model`.

## Tasks (`task_id` is a UUID or 8-character short code)

- `get_task`: `{ task_id }`
- `get_task_siblings`: `{ task_id }`
- `get_tasks`: `{ lifecycle?: "open"|"in_progress"|"implemented"|"blocked"|"done"|"dismissed"|"deferred"|"active"|"all", dismissal_category?: "duplicate"|"replaced"|"outdated"|"not_wanted", fields?: "full"|"compact", order_by?: "priority"|"created"|"last_activity"|"due", order_dir?: "asc"|"desc", limit?, offset?, agent_activity?: "idle"|"implementing"|"reporting"|"finished"|"failed", assigned_to?, parent_id?, source_session_id?, priority?: "low"|"medium"|"high"|"critical", type?: "feature"|"improvement"|"bug"|"investigation"|"general", tags?: string[], include_briefs?: boolean, signal_type?: "followup_required"|"agent_run_failed"|"deployment_failed"|"verification_failed"|"possibly_stale"|"blocked"|"implemented_unverified"|"superseded_pending"|"will_supersede", signal_bucket?: "action"|"risk"|"state", flagged?: boolean, requested_by?, request_origin?: "human_requested"|"agent_initiative"|"automatic"|"unattributed"|"nobody_asked"|"unrecorded"|"all" }` (prefer `fields: "compact"` and `limit: 20`; `parent_id` and `source_session_id` are full UUIDs; `assigned_to` and `requested_by` take `"me"` or a user UUID)
- `search_tasks`: `{ query, lifecycle?: "open"|"in_progress"|"implemented"|"blocked"|"done"|"dismissed"|"deferred"|"active"|"all", limit?, offset?, requested_by?, request_origin?: "human_requested"|"agent_initiative"|"automatic"|"unattributed"|"nobody_asked"|"unrecorded"|"all" }`
- `create_task`: `{ title, intent, description, acceptance_criteria?: string[], ai_instructions?, type?: "feature"|"improvement"|"bug"|"investigation"|"general", priority?: "low"|"medium"|"high"|"critical", tags?: string[], due_date?, testing_notes?, usage_notes?, human_only?: boolean, no_code?: boolean, is_brief?: boolean, is_experiment?: boolean, experiment_branch?, assigned_to?, session_id?, parent_task_id?, follow_up_from_task_id?, source_incident_id?, source_pull_request_id?, source_automation_run_id?, origin_reason?: "incident_fix"|"unlinked_commits"|"security_advisory"|"dependency_pr"|"automation_run", external_source?: "sentry"|"better_stack"|"github_issue"|"jira"|"plain"|"inbound_pipe", source_pipe_id?, external_id?, external_url?, idempotency_key, preview_ack? }` (`title` at most 115 characters; a fresh UUID `idempotency_key` on every create; `preview_ack` only after `preview_required`; which fields carry what, and the source and external-ticket links: `devspec-records.md`)
- `update_task`: `{ task_id, title?, description?, description_edits?: [{ op: "replace"|"append", find?, content }], intent?, acceptance_criteria?: (string|{id, text})[], ai_instructions?, testing_notes?, usage_notes?, tags?: string[], due_date?, priority?: "low"|"medium"|"high"|"critical", type?: "feature"|"improvement"|"bug"|"investigation"|"general", lifecycle?: "open"|"deferred"|"dismissed"|"blocked", dismissal_category?: "duplicate"|"replaced"|"outdated"|"not_wanted", target_task_id?, note?, parent_task_id?, is_brief?: boolean, human_only?: boolean, no_code?: boolean, is_experiment?: boolean, experiment_branch?, agent_branch?, agent_merged?: boolean, machine_user_id?, session_id?, assigned_to?, commit_sha?, reconcile_chore_outcome?: { chore_id, disposition: "transferred"|"nothing_needed"|"reconciled", summary }, external_source?: "sentry"|"better_stack"|"github_issue"|"jira"|"plain"|"inbound_pipe", source_pipe_id?, external_id?, external_url?, expected_version?, idempotency_key?, preview_ack? }` (prefer `description_edits`; send `expected_version` and a fresh `idempotency_key` on spec edits; `"dismissed"` needs `dismissal_category`, plus `target_task_id` for `"duplicate"` or `"replaced"` and a `note` for `"not_wanted"`; `note` replaces the completion note, so add context with `add_implementation_note` instead; `assigned_to: null` removes every assignee)
- `link_tasks`: `{ task_id, related_to_id, relationship: "caused_by"|"blocks"|"related_to" }`
- `reopen_task`: `{ task_id, reason_code: "implementation_incomplete_or_broken", note }` (for recorded work that does not do what was agreed; `note` says what is incomplete or broken)

## Claiming and delivering

- `reserve_work_items`: `{ task_ids: string[] }` (in the order you will work them)
- `claim_work_item`: `{ task_id, agent_branch, known_instruction_tiers_version?, known_instruction_tiers_hash?, force?: boolean, reason? }` (pass back `instruction_tiers_version` and `instruction_tiers_hash` from an earlier claim in this conversation so rules you already hold are not sent again; `force` needs `reason` and only explicit authority justifies it; the plugin adds `provider`)
- `release_work_item`: `{ task_id, reason?, force?: boolean }` (hand back a claim with nothing delivered; `force` needs `reason`)
- `fail_work_item`: `{ task_id, error, partial_work_notes?, conflict_context?: { conflicting_files?: string[], conflicting_commit_sha?, feature_branch?, conflicting_task_id?, conflict_description? } }`
- `add_implementation_note`: `{ task_id, content, session_id?, references?: [{ type: "url"|"file"|"commit", value }] }`
- `record_implementation`: `{ task_id, work_claim_ref?, affected_files?: string[], completion_summary?, completion_note?, completion_disposition?: "implemented"|"already_correct"|"partial"|"workaround", completion_confidence?, testing_notes?, usage_notes?, manual_followup_steps?: [{ description, kind?: "required_step"|"note" }], verification_report?: { verification_type?: "automated"|"human_required"|"partial", automated_checks_passed?: string[], human_review_needed?: string[], confidence? }, agent_merged?: boolean, merge_when_cleared?: boolean, pull_request_number?, pull_request_repo?, commit_sha?, commit_message?, provider?: "antigravity", runner_type?: "persistent"|"ephemeral", runner_hostname?, machine_user_id? }` (leave `commit_sha` out unless the result reports `commit_sha_source: "none"`; `merge_when_cleared: true` switches on Merge when cleared for the pull request carrying this task, or the one `pull_request_number` names; `completion_confidence` is 0 to 100 and `verification_report.confidence` 0 to 1)
- `add_commit_reference`: `{ commit_sha, commit_message?, task_id?, memory_id?, session_id? }` (only after `record_implementation` reports `commit_sha_source: "none"`; the commit as git shows it, never padded)
- `record_criterion_verdicts`: `{ task_id, work_claim_ref?, verdicts: [{ criterion_id, text, verdict: "met"|"not_met"|"unknown"|"intent_met", layer?: "api_test"|"cli_test"|"schema_check"|"browser_test"|"human_confirmation", evidence?: { action, result }, divergence?: { instead, serves_intent, why_better } }], requirement_evidence?: [{ criterion_id, requirement_id, coverage, note? }] }` (`criterion_id` is the full UUID from `get_task`; `met`, `not_met` and `intent_met` need `layer` and the `evidence` of what you ran and what came back; `intent_met` also needs `divergence`; `requirement_evidence` ties a `met` or `intent_met` verdict in this call to the requirement version it shows met, from `relevant_requirements` on the claim)

## Pull requests and dependency updates

- `get_pull_request`: `{ number?, repo?, pull_request_id? }`
- `record_dependency_review`: `{ number?, repo?, pull_request_id?, head_sha, findings, merge_when_cleared?: boolean, carries_pull_request_number? }` (your review of a Dependabot or Renovate pull request that changes only dependency files: `number` or `pull_request_id`; `head_sha` is the full commit you reviewed, from `gh pr view <number> --json headRefOid`; `findings` says which release notes you read, for which versions, what changed that touches this project, and which of its checks you ran with their results; review and record again after any push; `carries_pull_request_number` only on a pull request you opened to carry a bot's update unchanged; `merge_when_cleared: true` switches on Merge when cleared in the same call)

## Project incidents (`incident_id` is a UUID or 8-character short code)

- `get_incidents`: `{ scope?: "active"|"blocking"|"resolved"|"all", kind?: "deploy_failed"|"checks_failing"|"security_advisory"|"unlinked_work"|"undo_requested"|"followup_failed"|"reported", pull_request_id?, pull_request_number?, repo?, task_id?, include_recently_resolved?: boolean, offset?, limit? }`
- `get_incident`: `{ incident_id }`
- `report_incident`: `{ title, kind?: "reported"|"checks_failing"|"deploy_failed", summary?, fingerprint?, opened_reason?: "contributor_escalated"|"reported", repo?, branch?, check_name?, target_name?, advisory_id?, blocked_pull_request_id?, blocked_pull_request_number?, blocked_task_ids?: string[], block_reason?, signal_context?: {}, claim_immediately?: boolean, run_id? }` (`kind` defaults to `reported`; the other kinds open only from their own signals)
- `manage_incident`: `{ incident_id, action: "claim"|"release"|"heartbeat"|"awaiting_followup"|"escalate_needs_decision"|"resolve"|"link_blocked"|"unlink_blocked", run_id?, handler_label?, reason?, summary?, decision_prompt?, fix_task_id?, fix_pull_request_number?, blocked_pull_request_id?, blocked_pull_request_number?, repo?, blocked_task_ids?: string[], block_reason? }` (one handler at a time: another's claim is refused as `already_claimed`, naming the `holder`; a claim lapses after 15 minutes without a `heartbeat`. Once a pull request carrying your fix is waiting to merge, set the action to `awaiting_followup`, naming the fix, by `fix_task_id` or, for a fix that has no task, `fix_pull_request_number` (with `repo` when the number is ambiguous): the incident stays yours without heartbeats. Never `release` or `resolve` it, or unlink its fix task, while that fix is on its way.)
